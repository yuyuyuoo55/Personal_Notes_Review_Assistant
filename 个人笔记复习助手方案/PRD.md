# 个人笔记复习助手 PRD（v1）

## Agentic 问答规则（v1.1 增补）

- 快速模式由问答 Agent 判断是否需要笔记资料，而不是由前端或关键词规则强行决定。
- 快速模式下，问候、产品使用说明等基础问题由 Agent 直接回答；知识问题由 Agent 调用“检索个人笔记”工具。
- 精确查找不经过 Agent 判断，固定执行完整 Step RAG，用于用户主动要求更可靠检索时。
- 每次问答展示端到端耗时；资料不足或检索异常时，页面统一显示“没有找到对应片段”，不暴露内部字段或异常栈。

## 快速模式会话记忆（v1.2 增补）

- 快速模式按浏览器会话维护内存记忆：保留最近 3 轮原始问答；更早的内容压缩成一段摘要。
- 每次快速问答将“摘要 + 最近 3 轮 + 当前问题”交给 Agent，用于理解“我叫什么”“刚才那个”等追问。
- 精确查找不读取、不写入会话记忆，始终执行无状态的固定 Step RAG。
- 记忆不写数据库、不保存到文件；后端重启或浏览器建立新会话后会清空。

## 1. 产品一句话

把自己的课程讲义、Markdown 笔记或项目笔记导入后，用户可以围绕资料提问、查看原文出处，并按章节生成小测复习。

## 2. 用户与场景

**目标用户**：像小余一样，需要复习课程、整理技术笔记的大学生。

**核心场景**：

1. 复习前不知道某个概念在哪份笔记里。
2. 想问“RRF 和加权融合有什么区别”，但希望答案只依据自己的笔记。
3. 学完一章后，想快速做 3 道小题检查是否记住。

## 3. v1 功能

| 功能 | 用户能做什么 | v1 完成标准 |
| --- | --- | --- |
| 笔记库 | 导入 Markdown / PDF 笔记 | 显示已导入文件、分块数量与状态 |
| 智能带引用问答 | 输入学习问题并得到回答 | Agent 先判断是否需要查笔记；知识类问题走混合检索，每个回答至少展示 1 个原文来源 |
| 来源查看 | 点击来源回看相关原文 | 显示文件名、章节标题、片段内容 |
| 章节小测 | 选定一份笔记或章节生成 3 题 | 题目与答案均基于检索到的片段 |
| 学习记录 | 查看最近提问和小测 | 仅本地保存最近记录，不做账号体系 |

## 4. 不做什么

- 不做登录、多用户、云端同步、文件分享。
- 不做多 Agent、联网搜索、复杂长期记忆。
- 不承诺回答笔记之外的知识；无依据时拒答比编造更重要。
- 不追求大规模部署，先保证本机可跑、可演示。

## 5. 用户流程

1. 导入一组课程/技术笔记。
2. 系统按标题切分笔记，建立向量索引和 BM25 索引。
3. 用户选择“问笔记”或“章节小测”。
4. Agent 判断是否调用检索工具；需要检索时，系统先将口语化问题改写为独立检索问题，再完成向量检索、BM25、RRF 融合与 Cross-Encoder 精排。
5. 系统依据最终片段生成结果并展示出处。
5. 用户通过来源回看原文，或继续复习。

## 6. 实习作品的亮点

- 不是泛泛聊天机器人：答案有资料边界和可点击引用。
- 技术点来自已实操的学习内容：Markdown 结构化切分、查询改写、向量检索、BM25、RRF、Cross-Encoder 精排、Agent 工具调用、来源追溯、无命中拒答。
- 可以用自己的真实 RAG/Java/面试笔记现场演示，不依赖外部数据。

## 7. 验收标准

- 导入 3 份 Markdown 笔记后可稳定完成混合检索与精排。
- 10 个已知答案的问题中，至少 8 个能返回正确来源。
- 3 个笔记外问题均提示“当前笔记库资料不足”。
- 任意一份笔记可生成 3 道带答案和出处的复习题。
- 用户能在 3 分钟内演示：导入 → 问答 → 来源查看 → 小测。
# v1.1：双检索模式

## 新增用户需求

用户可在每次提问前选择检索模式，系统清晰说明速度与准确性的取舍，避免把高成本链路用于所有普通问题。

| 模式 | 用户可见说明 | 系统链路 | 成功标准 |
| --- | --- | --- | --- |
| 快速模式 | “仅向量检索，更快” | 原问题 → Chroma 向量检索 → Top-3 → 回答 | 常见概念问题能快速返回来源与答案 |
| 精确查找 | “改写 + 双路检索 + 精排，更准” | 查询改写 → 向量 + BM25 → RRF → Cross-Encoder → Top-3 → 回答 | 术语、缩写、函数名和跨表达问题能获得更可靠候选 |

基础问候（如“你好”“你是谁”）不进入笔记检索；笔记没有足够可靠资料时，返回诚实说明，不展示内部异常。
