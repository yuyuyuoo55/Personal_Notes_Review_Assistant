# 个人笔记复习助手：技术栈

## v1.1 增补

| 模块 | 技术 | 作用 |
| --- | --- | --- |
| 单 Agent 工具调用 | `ChatDeepSeek.bind_tools()` + Pydantic 工具 Schema | 快速模式中由模型决定是否调用笔记检索工具，并给出检索问题。 |
| 工具结果回传 | LangChain `ToolMessage` | 把真实检索片段交回 Agent，约束最终回答依据。 |
| 耗时观测 | Python `time.perf_counter()` + SSE | 记录端到端回答耗时，并展示在每条助手消息下。 |
| 精排模型准备 | Hugging Face 本机缓存 + SSE `stage` | 精确查找优先离线加载本机 Cross-Encoder；首次下载时前端展示准备进度。 |

本项目只采用小余已经学习、运行或能解释的技术；**不包含 RAGAS 评估**。

| 层级 | 技术 | 在项目中的作用 |
| --- | --- | --- |
| 开发语言 | Python | 后端、检索链路和数据处理 |
| 前端 | Streamlit | 笔记导入、问答、来源查看、小测页面 |
| 后端 | FastAPI | 对外提供导入、问答、小测接口，分离 UI 与检索逻辑 |
| RAG 框架 | LangChain | 文档对象、Markdown 切分、Tool 与 Agent 编排 |
| 查询优化 | DeepSeek Chat | 将口语化或含指代的问题改写为完整检索问题；失败时回退原问题 |
| 文档切分 | `MarkdownHeaderTextSplitter` | 按标题保留章节结构，便于来源定位 |
| 向量嵌入 | DashScope Embeddings | 把笔记和问题转为向量，完成语义检索 |
| 向量存储 | Chroma | 本地持久化保存笔记向量与来源元数据 |
| 稀疏检索 | `bm25s` + `pkuseg` | 中文分词后进行关键词检索，弥补纯向量对术语的不足 |
| 融合算法 | 手写 RRF | 合并向量检索与 BM25 的排序结果，不直接混比分数 |
| 精排模型 | `BAAI/bge-reranker-base` + `sentence-transformers` | 对 RRF 候选片段按“问题 + 片段”重新打分，留下最相关内容 |
| Agent（第二步接入） | LangChain `create_agent` + `@tool` | 在“笔记问答”和“章节小测”之间做受控工具路由；不是核心检索准确率的来源 |
| 大模型 | DeepSeek Chat | 基于最终检索片段生成回答与复习题 |
| 配置管理 | `.env` + `python-dotenv` | 读取 API 配置，不把真实密钥写进代码或仓库 |

## 端到端链路

```text
本地笔记
→ Markdown 标题切分
→ Chroma 向量索引 + BM25 索引
→ 用户提问
→ 查询改写（补全指代、保留技术关键词）
→ 向量检索 + BM25
→ RRF 融合
→ Cross-Encoder 精排
→ DeepSeek 仅依据最终片段回答
→ 答案 + 来源引用
```

## 本期明确不使用

- RAGAS、自动化评测集与评测看板
- 父子检索、多轮自检
- LangGraph、多 Agent、联网搜索
- 登录、多用户、云端同步和上线部署
# 双模式对应的技术使用

| 技术 | 快速模式 | 精确查找 |
| --- | --- | --- |
| DashScope Embeddings + Chroma | 使用 | 使用 |
| DeepSeek 查询改写 | 不使用 | 按需使用 |
| `pkuseg` + `bm25s` | 不使用 | 使用 |
| 手写 RRF | 不使用 | 使用 |
| `BAAI/bge-reranker-base` | 不使用 | 使用 |
| DeepSeek 基于资料回答 | 使用 | 使用 |

这样技术栈不是“所有请求全量调用”，而是由模式明确控制。
